# Recommendations

These are the choices built into the demo, and why.

## 1. How staff record time: timer first, typed-in as a backup

**Recommendation:** Use a start and stop timer as the main way. Allow typed-in hours only as a backup, with a reason.

**Why:**
- A timer is harder to fake than typed-in hours, so the client trusts it more.
- People still forget, or work off-site. The backup stops them from losing real hours.
- Typed-in entries are clearly marked "Typed in" so the manager checks them more closely.

**Every entry has:**
- Project and type of work (Development, Design, Meetings and so on)
- A short note on what was done (required, the client sees it)
- An optional proof link (a file, design, commit or ticket)

## 2. Approval: yes, by a manager

**Recommendation:** Every entry starts as "Awaiting approval". Only approved hours count against the 45 hours.

**Why:**
- It gives the client report credibility. Every line was checked by a manager.
- It stops double logging and mistakes.
- Rejecting needs a reason, so the staff member knows what to fix.
- To save time, the manager can approve all timer entries in one click and check typed-in entries one by one.

## 3. Client view: both a live report and a download

**Recommendation:** Give the client a read-only report page, and also let the manager download it (CSV, or print to PDF) to send by email.

**Why:**
- Some clients like to log in and check. Others just want a monthly email.
- The report opens with one clear sentence, for example: "Pillar 5 delivered 52.5 hours. That is 7.5 hours more than the 45 paid hours."
- Only approved hours show. Pending or rejected hours never reach the client.

## 4. The 2-week cycle

- 45 paid hours per 14 days, both can be changed in settings.
- Hours reset at the start of each cycle. Unused hours do not carry over.
- Hours above 45 are shown as **extra hours** (purple), not as an error. This is the main proof the client needs.
